# Memory Telemetry Checking Benchmark

This subdirectory (`1-Check/`) contains a self-contained research project analyzing the performance overhead of various memory checking methodologies in Node.js on Linux.

## Research Objective
To quantify the latency differences between polling memory status using native Node.js `os` modules, parsing the `/proc/meminfo` virtual filesystem, and spawning a shell process (`ps`) to fetch memory data.

## Project Structure

- `run_experiments.js`: A Node.js script that runs the benchmarking protocol and exports latency results.
- `plot_results.py`: A Python script utilizing Pandas and Seaborn to parse the results and generate graphical analysis.
- `results.csv`: The raw dataset generated by the experiments (1,000 iterations per method).
- `latency_plot.png`: A logarithmic boxplot visually comparing the execution time of the three methods.
- `paper.md`: The detailed research paper outlining hypothesis, methodology, and conclusions.

## Reproducing the Experiments

### 1. Run the Node.js Benchmark
Ensure you have Node.js installed.
```bash
node 1-Check/run_experiments.js
```
This will output `1-Check/results.csv`.

### 2. Generate the Plots
Ensure you have Python 3 and the necessary dependencies installed (`pandas`, `matplotlib`, `seaborn`, `tabulate`).
```bash
python3 1-Check/plot_results.py
```
This will output `1-Check/latency_plot.png` and `1-Check/summary_stats.md`.
